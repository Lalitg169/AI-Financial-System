# AI Financial System

Fraud detection, credit risk scoring and CPI forecasting, served through a
Flask API with a Streamlit dashboard.

All data is synthetic (generated by `data/generate_data.py`), so treat the
metrics as a sanity check, not as real-world performance.

## Models

| Task | Models | Notes |
|------|--------|-------|
| Fraud | Random Forest, Isolation Forest | 3% fraud. Class weights or SMOTE, tuned decision threshold |
| Credit risk | Logistic Regression, Decision Tree | Average of both probabilities, Low / Medium / High at 35% and 65% |
| Inflation | ARIMA(2,1,2) | 6-month forecast with confidence interval, 12-month backtest |

Preprocessing (imputer, scaler, encoders) is fitted on the training split
only and saved next to the models, so the API transforms input the same way
training did.

## Results

| Model | Metric | Value |
|-------|--------|-------|
| Random Forest | F1 / PR-AUC | 1.00 / 1.00 |
| Isolation Forest | F1 | 0.92 |
| Logistic Regression | ROC-AUC | 0.97 |
| Decision Tree | ROC-AUC | 0.94 |
| ARIMA | Backtest MAE (naive) | 0.78 (0.39) |

The fraud data is almost perfectly separable, which is why the Random Forest
scores 1.0. ARIMA loses to the naive "no change" forecast on the held-out
year because the series is seasonal. Both are known issues.

## Setup

```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python src/train_all.py            # add --smote to oversample fraud cases
```

## API

```bash
python api/app.py                  # http://localhost:5000
```

Or with Docker:

```bash
docker build -t ai-financial-system .
docker run -p 5000:5000 ai-financial-system
```

| Method | Endpoint | Description |
|--------|----------|-------------|
| POST | `/predict-fraud` | Score one transaction |
| POST | `/predict-fraud/batch` | Score up to 1000 transactions (`{"transactions": [...]}`) |
| POST | `/predict-credit` | Default probability and risk category |
| GET | `/forecast-inflation?steps=6` | CPI forecast, 1 to 24 months |
| GET | `/model-info` | Training time, metrics, model files |
| GET | `/health` | Health check |

Example:

```bash
curl -X POST localhost:5000/predict-fraud -H "Content-Type: application/json" \
  -d '{"amount": 1200, "time_of_day": 2, "transaction_freq": 18,
       "distance_from_home": 450, "v1": 2.5, "v2": -1.8, "v3": 2.1}'
```

```json
{
  "success": true,
  "prediction": {"label": "FRAUD", "rf_prediction": 1, "rf_probability": 1.0,
                 "threshold": 0.58, "iso_prediction": 1}
}
```

Credit requests take `age`, `income`, `loan_amount`, `loan_tenure`,
`credit_score`, `existing_loans`, `employment_type`
(`Salaried`, `Self-employed`, `Business`) and `education`
(`Graduate`, `Post-Graduate`, `Under-Graduate`).

The credit response also includes `top_factors`: the three inputs that
pushed the Logistic Regression score furthest from an average applicant,
e.g. `{"feature": "credit_score", "effect": "lowers risk", "weight": -2.1}`.

Every field is required. Invalid input returns `400` with a message, e.g.
`{"success": false, "error": "Missing required fields: amount"}`.

## Layout

```
api/app.py              Flask API
dashboard/              Streamlit app
data/generate_data.py   synthetic data
src/config.py           paths, feature lists, seeds
src/preprocessing.py    split, impute, scale, encode
src/fraud_detection.py  fraud models and threshold tuning
src/credit_risk.py      credit models
src/economic_trend.py   ARIMA, backtest
src/validation.py       request validation
src/model_store.py      cached model loading
src/train_all.py        trains everything, writes reports/metrics_report.json
models/                 saved models, scalers, encoders
```
